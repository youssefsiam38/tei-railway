# Security

## Reporting

Open an issue at https://github.com/youssefsiam38/tei-railway/issues for a problem with the wrapper.
Report anything in the application itself to
https://github.com/huggingface/text-embeddings-inference. Do not include credentials, tokens or
public hostnames in an issue.

## The central fact

From upstream's own command-line help, on `--api-key`:

> By default the server responds to every request. With an api key set, the requests must have the
> Authorization header set with the api key as Bearer token.

The option is `Option<String>` and nothing sets it for you. A deployment on a public hostname with
no key is an open embeddings endpoint: anyone who finds the URL can send text to it and consume the
CPU you are paying for. This template refuses to start without one.

## What the key covers

| Route | No key set (upstream default) | Key set (this template) |
|---|---|---|
| `/embed`, `/embed_all`, `/embed_sparse` | open | 401 without a bearer token |
| `/predict`, `/rerank`, `/similarity` | open | 401 |
| `/tokenize`, `/decode` | open | 401 |
| `/embeddings`, `/v1/embeddings` | open | 401 |
| `/info` | open | 401 |
| `/health`, `/`, `/ping` | open | **still open** |
| `/metrics` | open | **still open** |

The last two rows are deliberate upstream behaviour, not an oversight: a platform has to be able to
probe a service without holding a credential, and this template's healthcheck depends on it.
`tests/smoke.sh` asserts both halves of the table, so an upstream change to either would fail CI.

**`/metrics` is public.** It publishes Prometheus counters: request counts, durations, queue sizes,
the model id. No input text and no key. If that is more than you want to publish, point
`PROMETHEUS_PORT` somewhere you do not expose, or put the service behind Railway's own access
controls.

## Deliberately opting out

`TEI_ALLOW_PUBLIC=true` runs with no key at all. The container then logs a warning on every start.
Set it only when the instance is on a private network or behind another gateway that authenticates
for you. On a public Railway domain it means an open endpoint.

## The key upstream prints into your logs

Text Embeddings Inference logs its parsed arguments at INFO on every start, and `api_key` is not one
of the fields it redacts. Verbatim from a stock container:

```
Args { model_id: "BAA*/***-*****-**-v1.5", ..., api_key: Some("the-actual-key"), ... }
```

Note that it partially masks `model_id`, which is public, and prints the credential in full. On a
hosting platform that puts the key into the deploy log, where anyone with project access can read it
and where it stays for as long as logs are kept.

The wrapper filters the router's standard output and standard error through `sed`, replacing the key
with `***REDACTED***`, so it never reaches the platform's log collector. The pattern is handed to
`sed` on a pipe rather than on its command line, so the key does not appear in a process listing
either, and the router is still `exec`-ed so signals and exit status are unaffected.
`tests/smoke.sh` asserts both halves: the key is absent from the logs, and the line it came from is
still there with the redaction in place.

This is worth knowing if you run the upstream image without this wrapper: rotate the key after any
start whose logs were retained.

## Secrets

- `API_KEY` is generated by the template with `${{secret(32)}}` and is never printed by the wrapper.
  The start-up log reports its length, nothing more, and the router's own mention of it is redacted.
- The key is passed to the router through the environment, never on a command line, so a process
  listing inside the container does not show it.
- `HF_TOKEN`, if you use a gated model, is passed straight to the application. Upstream marks that
  field as redacted in its own logs.
- Nothing is baked into the image at build time. There are no credentials in the Dockerfile, in a
  build argument, or in any layer, and a static check asserts it.

## Rotating the key

Change `API_KEY` in the service variables and redeploy. There is no session state and nothing is
cached, so the old key stops working the moment the new instance takes over.

## Transport

Railway terminates TLS at its edge and the certificate covers the generated domain. Plain HTTP
redirects to HTTPS.

## Data handling

No request is stored. Text arrives, vectors leave, and nothing is written to the volume but the
model. A crash loses nothing because there is nothing to lose.

## Third-party calls made by the application

On the first start it downloads the configured model from the Hugging Face hub. After that it makes
no outbound calls; inference runs locally on the CPU.

## Updates

The upstream image is pinned by digest. A version bump is a pull request that changes the digest, is
tested by CI against the real image, and is released as a new wrapper tag. See `MAINTENANCE.md`.
